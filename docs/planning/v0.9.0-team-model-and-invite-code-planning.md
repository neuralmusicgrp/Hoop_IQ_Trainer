# v0.9.0 Team Model and Invite-Code Planning

## 1. Purpose

This planning release defines the future team data model and invite-code flow before implementation. It gives Hoop IQ Trainer a blueprint for coach accounts, player accounts, teams, assignments, roster membership, and progress syncing without changing the current public/offline app.

## 2. Release Type

Planning / Architecture / Product Roadmap

## 3. Version

v0.9.0-team-model-and-invite-code-planning

## 4. Why This Comes After v0.8.7 - v0.8.10

- v0.8.7 planned the future coach/player sign-in direction.
- v0.8.8 added non-functional coach/player sign-in mockups.
- v0.8.9 added local Coach / Player / Guest role selection for public offline mode.
- v0.8.10 audited encoding, structure, duplicate IDs, screen targets, JavaScript sanity, and `index.html` / `v3.0/hoop-iq-trainer-v3.html` app alignment.

These releases prepared the app for team-account planning without adding live authentication, backend code, or database behavior too early.

## 5. Future Team Model

The future team model should be small, private by default, and organized around coach-owned teams.

### User

A user represents a future signed-in person using the app.

```json
{
  "id": "user_123",
  "displayName": "Anthony Boyd",
  "email": "coach@example.com",
  "role": "coach",
  "createdAt": "2026-07-05T12:00:00Z",
  "lastActiveAt": "2026-07-05T12:30:00Z"
}
```

### Team

A team represents one coach-managed group.

```json
{
  "id": "team_123",
  "name": "Hampton Tigers 7th Grade",
  "coachId": "user_123",
  "inviteCode": "HOOP-2026",
  "createdAt": "2026-07-05T12:00:00Z",
  "archivedAt": null
}
```

### TeamMember

A team member connects a user to a team.

```json
{
  "id": "member_123",
  "teamId": "team_123",
  "userId": "user_456",
  "role": "player",
  "joinedAt": "2026-07-05T12:10:00Z",
  "status": "active"
}
```

### InviteCode

An invite code lets a coach privately invite players to a team.

```json
{
  "code": "HOOP-2026",
  "teamId": "team_123",
  "createdByCoachId": "user_123",
  "createdAt": "2026-07-05T12:00:00Z",
  "expiresAt": "2026-08-05T12:00:00Z",
  "maxUses": 20,
  "useCount": 4,
  "isActive": true
}
```

### Assignment

An assignment is a coach-created study set for a team.

```json
{
  "id": "assignment_123",
  "teamId": "team_123",
  "coachId": "user_123",
  "title": "Week 1 Ball Screen Reads",
  "description": "Study the core ball screen terms before practice.",
  "termIds": ["pistol", "spain", "short-roll"],
  "dueDate": "2026-07-12",
  "createdAt": "2026-07-05T12:20:00Z"
}
```

### PlayerProgress

Player progress records how a player is doing on a term inside a team context.

```json
{
  "id": "progress_123",
  "playerId": "user_456",
  "teamId": "team_123",
  "termId": "spain",
  "attempts": 8,
  "correct": 6,
  "missed": 2,
  "masteryStatus": "developing",
  "lastReviewedAt": "2026-07-05T12:40:00Z"
}
```

## 6. Invite-Code Flow

### Coach Flow

1. Coach signs in later.
2. Coach creates a team.
3. App generates an invite code.
4. Coach shares the code privately.
5. Player enters the code.
6. Player joins the team.
7. Coach sees roster and progress later.

### Player Flow

1. Player signs in later.
2. Player enters team code.
3. App validates code later.
4. Player joins team.
5. Player sees assigned terms later.
6. Player progress can sync later.

## 7. Privacy and Youth Safety Rules

- Collect minimal data.
- Do not create public player profiles.
- Do not allow open player search.
- Do not add player-to-player messaging at this stage.
- Coaches can only see their own team.
- Parent/guardian policy should be reviewed before youth account launch.
- Progress data should be private to the player, coach, and approved guardian/admin roles later.

## 8. Permissions Planning

### Coach

- Create and manage own team.
- Invite players.
- Assign terms.
- View team progress.
- Edit team language later.

### Player

- Join team.
- Study assigned terms.
- Take quizzes.
- View own progress.

### Guest

- Use public/offline study mode.
- No team join.
- No synced progress.

### Future Admin

- Manage app content.
- Moderate team issues.
- Resolve support cases.

## 9. Not Included In This Release

This release does not include:

- Real sign-in.
- Real invite codes.
- Backend validation.
- Database tables.
- Roster management.
- Assignment UI.
- Progress syncing.
- Permissions enforcement.
